# CODE-STYLE — developer 产物区代码风格与注释规范 v1.0

> 本文由 developer（R-003）依契约 D3 制定并维护，是 `developer/script/` 下全部代码的
> 风格契约；变更须先发 NOTIFY、给兼容期、并升版本号（契约 §2.1.4 接口冻结）。
> 制定原则：注释解释**意图与原因**，不是逐行翻译代码（反 DN8）；文档诚实优先（反 DN9）。

## 1. 适用范围与语言

| 目标 | 语言 | 说明 |
|---|---|---|
| Python 组件 | Python 3，**仅标准库** | 板端不可假设 pip / 外网可用，第三方依赖一律禁止 |
| C 接口 | C99 | 面向 X5 gcc 编译；开发机 MinGW gcc 13.2 自测 |
| 文档 | 简体中文 Markdown | 与任务书、需求拆解书同语种 |

## 2. 文件与结构

1. **文件头注释（Python docstring / C 文件头注释块）必备四要素**：
   所属任务（task_id）、本文件职责一句话、关键设计决策及原因、平台差异注意事项（如有）。
2. Python 每个模块 / 类 / 公开函数配 docstring，函数 docstring 说明
   「做什么 + 为什么这样设计 + 参数含义 + 返回值」；C 每个公开函数配中文头注释块。
3. 行宽目标 ≤ 100 列（文档与字符串不受此限），Python 缩进 4 空格，C 缩进 4 空格。
4. 命名：Python 模块 `snake_case`，类 `PascalCase`，常量 `UPPER_SNAKE_CASE`；
   C 函数前缀 `rmlog_`、宏前缀 `RMLOG_`、类型后缀 `_t`。
5. 单文件职责单一；模块按「格式 → 数据 → 写入 → 工具」分层，禁止反向依赖
   （如 format 不得 import writer）。

## 3. 注释规范（本框架 DN8 的落点）

- **必写**：文件头、函数头、所有非显然逻辑（并发约束、转义规则、平台差异、轮转时机、
  为什么先写临时文件再 rename 等）。
- **必不写**：逐行复述代码的噪音注释（如 `i += 1  # i 加一`）、空洞占位注释
  （如 `# TODO 待补充` 无内容）、失效注释（改代码必须同步改注释）。
- **注释写「为什么」**：能从代码本身看出来的「做什么」少写；设计取舍、坑点、
  边界条件必须写。
- Python docstring 用 `"""..."""` 三引号；C 注释用 `/* ... */`（不用 `//`，兼容 C89 工具链习惯）。

## 4. 可靠性与错误处理约定（rmlog 项目特化）

1. **日志组件自身不许抛异常打断业务**：写日志失败时静默降级（内存计数，
   由 selftest 主动检查），绝不在业务关键路径上因日志故障而崩溃。
2. **多进程写入安全靠 O_APPEND 一次 write 一条完整行**：不跨 write 拆行，
   这是行完整性的根基，任何改动须先复核此约束。
3. **错误码是跨端接口**：只能改 `rmlog/catalog.py` 单一来源后重新生成 C 头文件，
   禁止在 C 文件里手改错误码表（防两端漂移）。
4. **时间戳双轨制**：墙上时间（可读、可对表）与单调时间（防 NTP 跳变、可算间隔）
   每条事件都带，缺一不可。
5. **平台差异诚实标注**：Windows 自测结论不得表述为 Linux 已验证（TASK 增补第 3 条），
   平台相关代码处必须注释指出差异点。

## 5. 测试约定

- 自测统一入口 `python3 -m rmlog.selftest`，断言式（失败即报 FAIL 并给非零退出码）；
  测试运行原始输出保存到 `script/tests/`（文件名含日期与 `.log` 后缀）。
- 测试临时文件一律落在 `tempfile.mkdtemp()`，用完清理，不得污染产物区。
- 每个测试函数文件头注释标明覆盖的 AC 编号，方便审查对照。
