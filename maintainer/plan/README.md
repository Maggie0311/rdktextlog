# plan/ — 任务规划（PRR）

每次归档或较大规模的答疑开工前写一份 `PLAN-YYYYMMDD-<slug>.md`。

**无计划不动手**。计划在 `status: done` 之前可持续更新，但要保留变更理由。

**计划骨架（本节即全部要求）**：表头（计划 ID / 角色 / 关联邮件 / 创建时间 / 状态）+ 九节：
1 目标 / 2 约束 / 3 记忆依据 / 4 专业方法 / 5 步骤 / 6 接口与依赖 / 7 风险与回滚 / 8 验收 / 9 收工检查。

对本角色额外要求，计划中必须写明：
- 本次归档的 `task_id`、**两封确认通知的 mail_id** 与 commit hash；
- 说明书的**读者与阅读场景**（人类要据此维护 / 审查 / 裁决，侧重点不同）；
- 预计的**未解疑问**处理方式（发 QUERY 还是先标 `unverified`）。
