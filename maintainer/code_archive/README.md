# code_archive/ — 代码产物归档系统

> 所有者: `maintainer` (R-006) · **唯一写入者** · 本目录归档的是**代码产物**，不是邮件。

## 0. 与 `mailbox/archive/` 的区别（**必须区分**，委托层明确要求）

| | `code_archive/`（本目录） | `mailbox/archive/` |
|---|---|---|
| 归档什么 | **代码产物**（原件、带注副本、说明书、版本卡） | **邮件**（通信记录） |
| 组织维度 | **`task_id` + 版本号** | **`YYYY-MM`**（时间） |
| 检索问题 | "这个任务的第 3 版长什么样、为什么这么写" | "上个月谁跟谁说了什么" |
| 可否修改 | 原件**写入即冻结**；新增只能加版本 | 只读（邮件发出即冻结） |

**两处永不互相存放**：邮件留在邮箱；代码留在本目录。若某封邮件对归档有决定性作用（例如两方确认通知），
在**版本卡里引用其 `mail_id`**，而不是把邮件复制进来。

## 1. 目录结构（冻结）

```
code_archive/
├── README.md                本文件：归档规则
├── INDEX.md                 总索引：task_id / 版本 / commit / 验收状态 / 三份来源 mail_id / 配套文档
├── <task_id>/
│   ├── VERSION-<NNN>.md     版本记录卡（三份要件、补注前后双指纹、diff 结论、状态）
│   ├── SPEC-<NNN>.md        说明书（简洁总览；11 个冻结字段见 ../role-limit/ROLE-LIMIT.md §4）
│   ├── WALKTHROUGH-<NNN>.md 逐模块代码走读（教学向）
│   ├── QUESTIONS-<NNN>.md   关键问题清单（读码前自查）
│   ├── DIFF-<NNN>.md        与上一版差异（首版写「首版」）
│   └── code/                **带注代码**：从来源逐字节复制后就地补注；补注完成即冻结
└── _tombstones/             未采用 / 被验收驳回 / 被否决版本的墓碑记录（**不删**）
```

（另：项目级**术语表**在 `../script/GLOSSARY.md`，跨版本累积。）

## 2. 归档的前置条件（**硬性，三份要件缺一不可**）

| # | 要件 | 来源 | 作用 |
|---|---|---|---|
| 1 | **`accepted` 验收结论**（附理由） | `management` | **归档许可**——没有它就不能归档（委托层 2026-09-26 确认） |
| 2 | **合格确认通知** | `developer` | 归档备料（产物路径 / commit hash / 构建方式 / 自测证据 / 审查报告） |
| 3 | **合格确认通知** | `software_tester` | 归档备料（测试通过的角度 / 报告路径 / **未覆盖项**） |

- 要件 2 与 3 的 **commit hash 必须一致**，且与要件 1 所验收的版本一致；
- 三份的 `mail_id` 全部抄入版本卡；
- 缺任一份 → **不得归档**；缺哪份就向哪方发 `QUERY`；
- `management` 判 **`rejected`** → **不归档**；该版本进 `_tombstones/`（原因 = 验收驳回 + 理由）。

## 3. 补注、冻结与校验（委托层 2026-09-26 确认的方式）

**补注是就地做的**：从来源逐字节复制到 `code/` 后，**注释直接加在这些文件上**（不另存第二份）——
人类打开的就是带注的那份。**补注只允许新增以注释符号开头的行**（不改任何代码行，见 `../role-limit` §4 判定表）。

**冻结**：补注完成的那一刻起，`code/` 内文件**一字不改**；要变只能**新版本**（版本号递增）。

**双指纹**（记入版本卡，用于证明"只加了注释"）：

| 指纹 | 内容 |
|---|---|
| **补注前** | 来源 **commit hash** + 逐文件 **SHA-256 清单**（证明归档的是被审查、被测试过的那一份） |
| **补注后** | `code/` 逐文件 **SHA-256 清单**（证明当前归档件的实际内容） |

外加 **diff 结论**：补注前后 diff 必须**只含以注释符号开头的新增行**；不符合即违规（KN3）。

## 4. 大文件策略

二进制、打包件、构建中间物**不入库**：只记录**校验值 + 来源路径 + 重建方式**（可重建者优先重建，不可重建者记录获取方式）。

## 5. 墓碑

未采用或被否决的版本，在 `_tombstones/` 留一条记录（版本、原因、当时依据）。
**墓碑不删**——长期维护中最昂贵的问题是"当初为什么不那样做"。
