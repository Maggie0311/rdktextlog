# code_archive/ — 代码产物归档系统

> 所有者: `maintainer` (R-006) · **唯一写入者** · 本目录归档的是**代码产物**，不是邮件。

## 0. 与 `mailbox/archive/` 的区别（**必须区分**，委托层明确要求）

| | `code_archive/`（本目录） | `mailbox/archive/` |
|---|---|---|
| 归档什么 | **代码产物**（原件、带注副本、说明书、版本卡） | **邮件**（通信记录） |
| 组织维度 | **`task_id` + 版本号** | **`YYYY-MM`**（时间） |
| 检索问题 | "这个任务的第 3 版长什么样、为什么这么写" | "上个月谁跟谁说了什么" |
| 可否修改 | 原件**写入即冻结**；新增只能加版本 | 只读（邮件发出即冻结） |

**两处永不互相存放**：邮件留在邮箱；代码留在本目录。若某封邮件对归档有决定性作用（例如两方确认通知），
在**版本卡里引用其 `mail_id`**，而不是把邮件复制进来。

## 1. 目录结构（冻结）

```
code_archive/
├── README.md                本文件：归档规则
├── INDEX.md                 总索引：task_id / 版本 / commit / 状态 / 来源 / 说明书
├── <task_id>/
│   ├── VERSION-<NNN>.md     版本记录卡（来源、commit、SHA-256 清单、状态、验收回填、补注 diff 结论）
│   ├── SPEC-<NNN>.md        说明书（给人看；字段冻结见 ../role-limit/ROLE-LIMIT.md §4）
│   ├── original/            **冻结原件**（字节副本；写入后永不修改）
│   └── annotated/           带注副本（可选；与 original 的 diff **只含新增注释行**）
└── _tombstones/             未采用 / 被否决版本的墓碑记录（**不删**）
```

## 2. 归档的前置条件（**硬性**）

1. **`developer` 与 `software_tester` 的合格确认通知齐备**，且二者的 **commit hash 一致**；
2. 确认通知的 `mail_id` 已抄入版本卡；
3. 缺任一条 → **不得归档**；缺哪封就向哪方发 `QUERY`。

## 3. 冻结与校验

- `original/` 写入后**永不修改**；要变只能作为**新版本**（版本号递增）；
- 版本卡记录 **SHA-256 清单**（逐文件），供日后校验"归档件是否被动过"；
- `annotated/` 与原件的 **diff 必须只含新增注释行**；该结论须记入版本卡。

## 4. 大文件策略

二进制、打包件、构建中间物**不入库**：只记录**校验值 + 来源路径 + 重建方式**（可重建者优先重建，不可重建者记录获取方式）。

## 5. 墓碑

未采用或被否决的版本，在 `_tombstones/` 留一条记录（版本、原因、当时依据）。
**墓碑不删**——长期维护中最昂贵的问题是"当初为什么不那样做"。
