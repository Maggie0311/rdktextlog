## 0. 一句话结论

**v3 是在 v2 之上"加自动层"，不是"换掉"**：v2 的全部用法（`rmlog.event()`、`Writer.event()`、`AsyncWriter.emit()`、`Session`、C 宏、LOGV1 行格式、五域 24 错误码、`rmlog_read` 基础过滤）**原样保留、全兼容**；v3 新增的是"赛场自动记录 + 场下秒定位"的上半层——黑匣子环形缓冲、崩溃遗言、dmesg/资源/通信自动监控、心跳看门狗、字符串+24bit 双轨错误码、Linux/STM32 公共头、日志统计 CLI，并提供一个把日志/黑匣子/会话合成一处的 `LogRuntime` 入口。解决的是 v2 没覆盖的"错误发生前几秒现场没留""内核/资源异常没转成错误码""主循环卡死没人发现""跨端错误码两份手抄会漂""场下翻日志慢"这五类问题。

## 1. v3 相比 v2 新增了什么功能

| 功能 | 是什么 | 为什么加（解决什么痛点） | 对应文件 / 依据 |
|---|---|---|---|
| **黑匣子环形缓冲 + 错误前快照** | `BlackBox` 只在内存里保存最近 `capacity` 条高频样本（`record` 追加进 `deque(maxlen=capacity)`），正常不碰磁盘；ERROR/FATAL 时 `snapshot(reason, code)` 把当前窗口原子写成 JSONL 快照（`mkstemp`→写 header+行→`fsync`→`os.replace` 原子落名→`_prune_snapshots` 按 `max_snapshots` 淘汰） | 比赛高频数据（底盘/IMU/状态机）全程落盘会拖慢控制线程又刷爆磁盘；"错误发生前几秒"的现场比错误本身更能定位根因。IMPL P0 | `rmlog/blackbox.py`：类 :16、`record` :83、`snapshot` :94（`mkstemp` :105、`fsync` :113、`os.replace` :114）、`_prune_snapshots` :31（`max_snapshots==0` 不淘汰 :33-34） |
| **崩溃遗言（保留 core dump）** | `install_signal_hooks` 给 SIGABRT/SIGBUS/SIGFPE/SIGSEGV 预装 handler，进程被打死前在**预打开的 fd** 上写一行 `CRASH\|signal=N\|pid=M`（所有格式化/分配都在安装期做完）；写完恢复 `SIG_DFL` 再 `os.kill` 重抛同信号，尽量让内核走"默认动作=core dump"路径 | Python 进程段错误/被信号打死时普通日志往往来不及落盘最后一刻；遗言 + 重抛两条都尽量保住，是否真落 core 仍看板端 `ulimit`/`core_pattern` | `rmlog/crash.py`：`EmergencyWriter` :7（预打开 fd :13）、`install_signal_hooks` :30、handler :40-48（`os.write` :42、`SIG_DFL` :47、`os.kill` :48） |
| **通信监控 `CommStats`** | 通信层显式调 `success()`/`failure()`，`CommStats` 用滑动窗口 `_outcomes=deque(maxlen=rate_window)` 统计错误率；**连续 `window` 次失败 → `E-COMM-004`（链路中断）**，分散失败/短时突发 → `E-COMM-003`（抖动） | 区分"链路真断了"和"偶尔丢包噪声"，避免误停机；库**不拦截 SPI/CAN 驱动**，事实由业务回调提供。IMPL §4 第 4 条 | `rmlog/monitors.py`：`CommStats` :10、`failure` :30、三路判定 :38-45（`interrupted`→E-COMM-004 :45，其余→E-COMM-003） |
| **dmesg / 温度 / 电压 / 内存监控** | `DmesgMonitor` 跑真实 `dmesg --follow --time-format iso` 子进程，命中 `PATTERN` 的行映射 `E-COMM-002`（spi/can/i2c）或 `E-HW-003`（其它）；`ResourceMonitor` 周期读 sysfs/procfs（温度/电压/内存），越限映射 `E-HW-002`（>85000m°C）/`E-HW-001`（<14000mV）/`E-SYS-001`（<32768kB） | 内核异常与系统资源越限自动转成业务可查的错误码，场下不用手动翻 dmesg/sysfs。IMPL P1 | `rmlog/monitors.py`：`DmesgMonitor` :83（`PATTERN` :86、`run` :109、`stop` 终止并等子进程 :139）；`rmlog/resources.py`：`ResourceMonitor` :10、`_linux_values` :30、`check_once` :48 |
| **心跳看门狗 + systemd `WatchdogSec`** | 应用层 `HeartbeatWatchdog` 独立线程每 `interval` 读 `runtime.health_attrs()` 的心跳 age，超 `timeout` 发 `E-FSM-003`；daemon 主循环每 0.5s `heartbeat("main")` + `sd_notify("WATCHDOG=1")`，服务文件 `WatchdogSec=2` 让 systemd 兜底重启 | 主循环卡死/死锁也能被"喂狗超时"发现；应用层记错误码 + systemd 层兜底重启两层。IMPL P1 | `rmlog/monitors.py`：`HeartbeatWatchdog` :53（`_run` :71-80）；`rmlog/daemon.py`：`main` :37（watchdog `timeout=1.5, interval=0.1` :48、主循环 :59-61、`sd_notify` :19）；`systemd/rmlog-demo.service`：`WatchdogSec=2` :7 |
| **错误码字符串 + 24bit 双轨** | `code_map.encode/decode/hex_code` 把字符串码映射为 24bit 整数 `domain(8)\|level(4)\|number(12)`（如 `E-COMM-004`→`0x223004`）；字符串码仍是日志主显示，bit 码用于跨端紧凑传输，高 8 位保留为零可放 uint32_t | 下位机/跨进程传输用紧凑整数，避免传可变长度字符串；未知码不破坏旧文本日志。IMPL §bit 编码冻结 | `rmlog/code_map.py`：`DOMAIN_IDS`/`LEVEL_IDS` :10-11、`encode` :14、`decode` :26、`hex_code` :37 |
| **Linux/STM32 公共头文件单源生成** | `gen_code` 从单一来源 `catalog.py` 生成 C 端 `rmlog_errors.h` 与 Linux/STM32 共用 `shared/rmlog_schema.h`（每码 `RMLOG_CODE_*`/`RMLOG_LVL_*`/`RMLOG_BIT_*` 三宏 + 码表 + 五域） | 双端错误码表从"两份手抄"变"单一来源生成"，杜绝漂移；下位机（STM32/RT-Thread）与 Linux 引用同一份。IMPL P2 | `rmlog/gen_code.py`：`render_header` :65、`write_schema` :140；`shared/rmlog_schema.h`：24 码 + 三宏（`RMLOG_BIT_COMM_004` :54） |
| **日志统计 CLI** | `rmlog_read.py stats <log>` 按错误码/级别统计频次（总事件 + 级别分布 + 各码次数 + 残行计数打到 stderr） | 场下先看"哪类错误最多"，再决定 filter 钻哪条，减少翻日志时间。IMPL P2 | `rmlog_read.py`：`cmd_stats` :239-254、subparser :281 |
| **`LogRuntime` 一键初始化** | 把日志写入、黑匣子采样、会话属性合成一个对象；`heartbeat`/`sample`/`emit` 统一入口；`emit` 遇 ERROR/FATAL **自动** `blackbox.snapshot("error", code)` 并补一条 `E-SYS-005`（带 `path`） | 业务不必每处手写 `Writer` + `BlackBox` + `session.attrs` 拼接；"出错自动留现场"对业务透明。IMPL P0/P1 | `rmlog/auto.py`：`LogRuntime` :16、`__init__` :19、`emit` :41（自动快照 :56-61、失败计 `blackbox_failures` :66）、`health_attrs` :69 |

> **重要事实（避免误读）**：v3 **没有新增错误码**——错误码表仍是 v1 的 24 码（`shared/rmlog_schema.h:137` `RMLOG_ERROR_TABLE_LEN 24`）。v3 新增的是"把系统/资源/通信事实**自动捕获并映射到既有错误码**"的层 + 双轨 bit 码 + 公共头 + 统计 CLI。v3 也**不改** LOGV1 行格式与 C 端 `rmlog.c`/`rmlog.h` 协议逻辑（SPEC-001 §2 明说"本轮未改 C 逻辑"）。

## 2. 用户使用方法

### 2.1 怎么初始化（`LogRuntime` 一个入口 / 分模块导入）

**推荐：一个 `LogRuntime` 全包**（日志 + 黑匣子 + 会话合成一处）：

```python
from rmlog.writer import Writer
from rmlog.session import Session
from rmlog.auto import LogRuntime

session = Session("match")                              # 会话标识，便于跨文件/跨启动过滤
writer = Writer(log_dir="/userdata/rmlog")              # 同步 Writer（1kHz 控制线程可换异步版）
runtime = LogRuntime(writer, "/userdata/rmlog/blackbox",   # auto.py:19：writer, blackbox_dir, capacity=2000, session=None
                     capacity=2000, session=session)
```

**异步版**（控制线程怕被磁盘 IO 卡住时用，`daemon.py:44-46` 同款）：

```python
from rmlog.async_writer import AsyncWriter
writer = AsyncWriter(Writer(log_dir="/userdata/rmlog"), session=session)
runtime = LogRuntime(writer, "/userdata/rmlog/blackbox", session=session)
```

**分模块导入**（不想要 `LogRuntime`，只单独用黑匣子/遗言）：

```python
from rmlog.blackbox import BlackBox
bb = BlackBox("/userdata/rmlog/blackbox", capacity=2000, max_snapshots=16)  # blackbox.py:19
bb.record("chassis", vx=1.2)                       # 只进内存
path = bb.snapshot("error", "E-COMM-004")          # 手动倒快照（LogRuntime 会替你自动倒）

from rmlog.crash import install_signal_hooks
install_signal_hooks(runtime, directory="/userdata/rmlog/crash")   # 装崩溃遗言钩子（crash.py:30）
```

> **事实注（导入方式）**：v3 的新能力经**子模块导入**（`from rmlog.auto import LogRuntime`、`from rmlog.blackbox import BlackBox`、`from rmlog.monitors import CommStats/HeartbeatWatchdog/DmesgMonitor`、`from rmlog.resources import ResourceMonitor`），**不是** `rmlog.LogRuntime`——`rmlog/__init__.py` 顶层 `__all__` 仍是 v1 集合，本轮只**新增**了 `encode_code`/`decode_code`/`hex_code` 三个双轨码入口（`__init__.py:30、39`）。旧代码 `import rmlog; rmlog.event(...)` 不受影响。

### 2.2 怎么周期性喂心跳 + 高频样本（黑匣子样本）

```python
runtime.heartbeat("main", count=1)                  # 喂主循环心跳，并自动进黑匣子样本（auto.py:34-39）
runtime.sample("chassis", vx=1.2, vy=0.0, wz=0.1)   # 高频样本：只进内存、不落盘（auto.py:30-32）
runtime.sample("imu", yaw=3.0, pitch=0.1, roll=0.2)
runtime.emit("E-INIT-000", "ctrl", "控制线程就绪")  # 写一条事件（auto.py:41）
```

> `sample`/`heartbeat` 的样本只进 `BlackBox` 的内存 `deque`（`blackbox.py:83-92`），**正常不碰磁盘**；字段开放，业务自行约定（如底盘指令、IMU、状态机、通信、电压/温度）。

### 2.3 怎么启动通信 / 资源监控器

```python
from rmlog.monitors import CommStats, HeartbeatWatchdog, DmesgMonitor
from rmlog.resources import ResourceMonitor

comm = CommStats(runtime, "spi", fail_threshold=3, rate_window=20)  # monitors.py:13
# 在业务通信回调里显式报告成败（库不拦截驱动）：
comm.success()                       # 一次成功
comm.failure("timeout")              # 一次失败；连续/抖动阈值触发 E-COMM-004/003

watchdog = HeartbeatWatchdog(runtime, name="main", timeout=1.0, interval=0.1)
watchdog.start()                     # 独立线程；喂狗超时发 E-FSM-003（monitors.py:53-80）

res = ResourceMonitor(runtime, interval=1.0)   # 周期读温度/电压/内存，越限发 E-HW-002/001、E-SYS-001
res.start()                          # resources.py:68-78

dmesg = DmesgMonitor(runtime)        # 默认 source=None → 真实 dmesg --follow（monitors.py:109-118）
# dmesg.run() 是阻塞监听，需放进独立线程；stop() 会终止并等待子进程（monitors.py:139-144）
```

> **事实注（谁负责启动谁）**：`daemon.py` 的常驻入口**只自动接 `HeartbeatWatchdog`**（`daemon.py:48`），`CommStats`/`ResourceMonitor`/`DmesgMonitor` **由业务自行 `start()`**（daemon.py 未启动它们）。

### 2.4 出错时**自动**发生什么

| 出错情形 | 自动行为 | 依据 |
|---|---|---|
| 写一条 **ERROR/FATAL** 事件 | `LogRuntime.emit` 立即 `blackbox.snapshot("error", code)` 倒出错误前窗口 → 成功补写一条 `E-SYS-005`（attrs 带 `path`）；倒快照失败计 `blackbox_failures += 1`（**该行为由 effective level 驱动，与事件本身是否写成功无关**） | `rmlog/auto.py:56-66` |
| 进程被 SIGABRT/SIGBUS/SIGFPE/SIGSEGV 打死 | 预装 handler 在 `crash-<pid>.log` 写一行 `CRASH\|signal=N\|pid=M`，再恢复 `SIG_DFL` 重抛以保留 core（是否真落 core 看板端 `ulimit`/`core_pattern`） | `rmlog/crash.py:40-48`（文件 :12、内容 :17） |
| 通信连续失败 / 抖动 | `CommStats` 自动发 `E-COMM-004`（连续中断）/`E-COMM-003`（抖动） | `rmlog/monitors.py:45` |
| 主循环喂狗超时 | `HeartbeatWatchdog` 自动发 `E-FSM-003`；systemd 层 `WatchdogSec=2` 兜底重启 | `rmlog/monitors.py:76`、`systemd/rmlog-demo.service:7` |
| 内核可疑行（spi/can/i2c/…） | `DmesgMonitor` 自动发 `E-COMM-002`/`E-HW-003` | `rmlog/monitors.py:130` |
| 温度/电压/内存越限 | `ResourceMonitor` 自动发 `E-HW-002`/`E-HW-001`/`E-SYS-001` | `rmlog/resources.py:57-65` |

黑匣子快照文件名：`blackbox-<wallsec>-<mono_ns>-<pid>-<seq>.jsonl`（`blackbox.py:103-104`）；首行是 header `{reason, code, count}`，后续每行一条窗口样本。

### 2.5 赛后怎么查

```bash
python3 rmlog_read.py stats rmlog.log                          # 按错误码/级别统计频次（rmlog_read.py:239-254）
python3 rmlog_read.py filter rmlog.log --level ERROR --code E-COMM-*   # 按码前缀过滤
python3 rmlog_read.py filter rmlog.log --session <id>                 # 按会话过滤（rmlog_read.py:226）
```

黑匣子快照直接看（回放错误前窗口）：

```bash
cat /userdata/rmlog/blackbox/blackbox-*.jsonl   # 首行 header，之后是错误前的内存样本
```

> **三件事速记**：① **初始化**——`runtime = LogRuntime(writer, "<dir>/blackbox", session=session)`（或分模块 `BlackBox`/`install_signal_hooks`）；② **喂数据**——`runtime.heartbeat("main")` + `runtime.sample(kind, **v)` + `runtime.emit(code, module, msg)`，ERROR/FATAL 自动倒快照；③ **查日志**——`python3 rmlog_read.py stats|filter <log>` + `cat blackbox-*.jsonl`。

## 3. 注意点 / 迁移（上手前必读）

| 注意点 | 说明 | 依据 |
|---|---|---|
| **异步队列满会丢事件（`dropped` 非零 = 丢过）** | `AsyncWriter` 只承诺"非阻塞入队便利"，不提供硬实时或零丢失；队列满 `put_nowait` 抛 `queue.Full` → `dropped += 1` 且返回 `False`（`async_writer.py:35-37`）。`LogRuntime` 里用 AsyncWriter 时该 `False` 会计入 `runtime.write_failures`（`auto.py:53-54`）；应把 `dropped`/`write_failures` 接入健康监控 | `async_writer.py:35-37`；`auto.py:53-54`；IMPL §4 |
| **黑匣子快照保留上限 `max_snapshots`（默认 16，0=无限）** | 每次 ERROR/FATAL 都倒一份快照，默认只保留最近 16 份、按文件名淘汰最旧；`max_snapshots=0` 表示**不淘汰、无限保留**，需自行规划磁盘。快照文件名按墙钟+单调序，NTP 回拨可能错序，但不影响"封顶磁盘"目标 | `blackbox.py:19-29、31-44`；IMPL §2、SPEC-001 §9 |
| **板端 core dump 默认是关的，需放开 `ulimit`** | 板端实测 `ulimit -c` = `0`（core 禁用）、`core_pattern=core`、`core_uses_pid=1`；崩溃遗言代码路径已测，但要真生成 core 文件须先放开 `ulimit` 并配置 `core_pattern` 落点 | `crash.py:44-48` 注释；板端报告 BQ4（§5.7、§8 第 4 条） |
| **下位机共用的 `rmlog_schema.h` 是生成物，勿手改** | 一条命令从 `catalog.py` 生成 C 端 `rmlog_errors.h` 与 `shared/rmlog_schema.h`；改错误码只改 `catalog.py` 后重新生成，双端不一致属缺陷 | `gen_code.py:202-218`（`python3 -m rmlog.gen_code`）；`rmlog_schema.h:2-7` |
| **systemd 服务实装 + `WatchdogSec` 重启待板端（`unverified`）** | 服务模板 `ExecStart=/usr/bin/python3 -m rmlog.daemon /userdata/rmlog`、`WorkingDirectory=/opt/rdk_x5_software/developer/script`、`WatchdogSec=2`；板端只做了临时目录跑 daemon 验证心跳/收尾（BQ5），**未安装服务**，实际 WatchdogSec 重启未测 | `systemd/rmlog-demo.service:7-9`；板端报告 §5.8、§7 |
| **开发机默认目录 `/userdata` 不存在，需显式指定目录** | `Writer()` 不带 `log_dir` 时默认 `/userdata/rmlog`，不存在则回退 `/var/log/rmlog`（`writer.py:78-79、178-192`）；开发机/Windows 上无 `/userdata`，用 `Writer(log_dir="./mylog")` 或 `set_default_writer(Writer(log_dir=...))`（`writer.py:509`，放在 `import rmlog` 之后、首次 `rmlog.event()` 之前）改目录 | `writer.py:78-79、509` |
