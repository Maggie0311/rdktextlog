## 0. 一句话结论

**v2 是在 v1 之上"加层"，不是"换掉"**：v1 的全部用法（`rmlog.event()`、C 宏、LOGV1 行格式、五域错误码、`rmlog_read` 基础过滤）**原样保留、全兼容**；v2 新增的是六块能力（异步入队、会话标识、五域检测适配、无人值守服务、一键证据导出、会话过滤），解决的是 v1 没覆盖的"控制线程不能卡""跨启动/跨文件串不起来""赛后取证要一键""无人值守要自启"这四类问题。

## 2. 使用方法是否有不同

### 2.1 完全不变（v1 用法全兼容）

| 用法 | 结论 | 依据 |
|---|---|---|
| `rmlog.event(code, module, message, attrs=...)` | **不变**，同步写入接口照旧可用 | `rmlog/__init__.py:29` 仍导出 `event/Writer/get_writer/set_default_writer`；`writer.py` 与 v1 同源（VERSION-001 §3 指纹表，仅 +注释行） |
| C 端 `RMLOG_I/W/E/F` 宏族 | **不变** | `rmlog/rmlog.h`、`rmlog/rmlog.c` 与 v1 同源（VERSION-001 §3 指纹表） |
| LOGV1 行格式 | **不变** | `rmlog/format.py` 唯一权威定义，与 v1 同源 |
| 五域错误码（24 码） | **不变** | `rmlog/catalog.py` 属 20 个未补注文件（与来源逐字节一致，VERSION-001 §4） |
| `rmlog_read.py` 基础过滤（`--level`/`--code`/`--since`/`--until`、`parse`/`tail`） | **不变** | `rmlog_read.py` 与 v1 同源；`--session` 只是**新增**参数，原参数语义不变 |

### 2.2 新增 / 推荐的用法

```python
# ① 会话绑定（推荐：让事件带上 session/pid，便于按场次/启动过滤与导出对账）
from rmlog.session import Session
from rmlog.async_writer import AsyncWriter
from rmlog.writer import Writer
session = Session("match")                    # session.py:7
w = AsyncWriter(Writer(log_dir="/userdata/rmlog"), session=session)   # daemon.py:20-21 同款
w.emit("E-INIT-000", "ctrl", "上电完成")       # 入队即返回，不落盘阻塞
# 或走同步 Writer：session.event(w, ...) / session.wrap(w) 传给业务组件
```

```bash
# ② 会话过滤（读端）
python3 rmlog_read.py filter rmlog.log --session <id>          # rmlog_read.py:225-226

# ③ 一键证据导出（业务日志 + journal + dmesg + 版本，逐项降级不伪造）
python3 export_evidence.py rmlog.log evidence --session <id>   # export_evidence.py:18
```

> **事实注（导入方式）**：v2 的新能力经**子模块导入**（`from rmlog.session import Session`、`from rmlog.async_writer import AsyncWriter`、`from rmlog.checks import emit_check`），**不是** `rmlog.AsyncWriter`——`rmlog/__init__.py` 顶层 `__all__` 仍是 v1 集合（`__init__.py:35-39`）。`daemon.py:8-10`、`fault_demo.py:5-7` 的 import 方式即官方示例。旧代码 `import rmlog; rmlog.event(...)` 不受影响。

### 2.3 迁移注意点（上手前必读）

| 注意点 | 说明 | 依据 |
|---|---|---|
| **异步队列满会丢事件（`dropped` 非零 = 丢过）** | `AsyncWriter` 只承诺"非阻塞入队便利"，**不提供硬实时或零丢失承诺**；队列满时 `emit` 返回 `False` 且 `dropped += 1`，调用方应把 `dropped` 计数接入健康监控 | `async_writer.py:35-37`；v2-USAGE「故障与队列边界」节；IMPL 第 4 条 |
| **故障注入需业务提供事实，库不自动探测硬件** | 库**不读取** SPI/CAN/电机状态；五域检测由业务回调提供事实，`emit_check` 只做"事实→错误码"映射 | `checks.py:1-5、8-12`；v2-USAGE「故障与队列边界」节 |
| **systemd 单元路径/权限待板端确认（未实装）** | `systemd/rmlog-demo.service` 的路径、用户、`/userdata/rmlog` 权限必须在 X5 上确认；**当前开发机测试结果不代表板端已验证** | v2-USAGE「证据与平台边界」节；SPEC-001 §10 |
| **开发机默认目录 `/userdata` 不存在** | 开发机/Windows 上无 `/userdata` 分区，直接跑会在创建默认目录时报错；需 `set_default_writer(Writer(log_dir="./mylog"))` 改目录（放在 `import rmlog` 之前） | `developer/script/USAGE.md` §1.1 |
| **旧日志没有 `session` 属性，不能按 session 查** | v1 及更早日志无 `session` 字段，`--session` 过滤对它们零命中（不误匹配、也不命中）；旧日志按文件/时间/错误码查 | v2-USAGE「会话」节；IMPL 第 2 条 |
