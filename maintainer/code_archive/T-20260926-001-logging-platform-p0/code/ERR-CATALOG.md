# ERR-CATALOG — rmlog 错误码表（表版本 1.0）

> **本文件是生成物（勿手改）**：由 `python3 -m rmlog.gen_code --doc` 从
> `rmlog/catalog.py` 生成 —— catalog.py 是唯一数据源；改错误码请改表后重新生成。
> 级别从低到高：`INFO < WARN < ERROR < FATAL`（含义见 `USAGE.md` §4）。

错误码格式：`E-<域>-<3位序号>`。五域：`INIT`、`COMM`、`HW`、`FSM`、`SYS`。

## INIT 域 — 初始化域：组件启动、配置加载、自检等初始化阶段事件

| 错误码 | 默认级别 | 中文含义 | 建议动作 |
|---|---|---|---|
| `E-INIT-000` | INFO | 组件初始化完成（rmlog 自身或业务组件启动就绪） | 无需处理；用于确认上电后组件存活时序 |
| `E-INIT-001` | ERROR | 组件初始化失败（打开设备/加载配置/创建线程失败） | 场下查看该行 k=v 属性中的组件名与 errno，先查设备树/路径/权限 |
| `E-INIT-002` | FATAL | 关键组件初始化失败，系统无法进入比赛模式（如控制主循环外设缺失） | 立即停机排查；比赛场上禁止带病上场，先修复再上电 |
| `E-INIT-003` | WARN | 组件初始化降级（非关键组件失败，功能受限但可继续运行） | 记录现象继续比赛；赛后复盘该组件，避免降级常态化 |
| `E-INIT-004` | ERROR | 配置参数非法或读取失败（配置文件缺失/类型不符/数值越界） | 核对最近改动的配置项与单位（rad/deg、ms/s 常见混淆） |

## COMM 域 — 通信域：SPI/CAN/串口/网络等链路的传输超时、校验失败、中断

| 错误码 | 默认级别 | 中文含义 | 建议动作 |
|---|---|---|---|
| `E-COMM-001` | ERROR | SPI 传输超时（从机未在时限内应答） | 检查从机供电/复位/接线；统计发生频率，连续出现即按链路故障处理 |
| `E-COMM-002` | ERROR | SPI/CAN 传输校验失败（CRC 或帧头不符，数据不可信） | 丢弃该帧并重传；频发时查线缆屏蔽与共地 |
| `E-COMM-003` | WARN | 通信链路抖动（短时丢包/重传率上升，未达到中断阈值） | 场上无需处理，观察是否升级为 E-COMM-004；赛后查电磁环境 |
| `E-COMM-004` | ERROR | 通信中断（连续多次失败，链路判定丢失） | 触发安全态（停止输出），检查两端连接器是否松脱 |
| `E-COMM-005` | WARN | 通信数据越界（协议字段超出物理合理范围，疑似错位或固件不匹配） | 核对两端协议版本与字节序；单次出现可忽略，连续出现按版本不匹配排查 |

## HW 域 — 硬件域：电源电压、温度、传感器等物理量越限或异常

| 错误码 | 默认级别 | 中文含义 | 建议动作 |
|---|---|---|---|
| `E-HW-001` | ERROR | 电源电压越限（电池电压低于比赛安全阈值） | 立即安排换电池；同时回看 E-HW-005 出现时间，评估耗电异常 |
| `E-HW-002` | ERROR | 温度越限（BPU/CPU/电调温度超过阈值） | 降负载或停机散热；检查散热接触与风道是否被遮挡 |
| `E-HW-003` | WARN | 传感器数据异常（IMU/编码器输出突变、冻结或 NaN） | 标记该传感器数据不可信；检查插接件与标定 |
| `E-HW-004` | FATAL | 硬件自检失败（上电自检未通过，禁止进入比赛模式） | 停机，按 k=v 属性中自检项逐项排查后再上电 |
| `E-HW-005` | WARN | 电压接近下限（预警带，提示电量即将不足） | 规划换电池时机（回库/间歇），不必立即停机 |

## FSM 域 — 状态机域：比赛/控制状态机的跃迁合法性、超时、未定义状态

| 错误码 | 默认级别 | 中文含义 | 建议动作 |
|---|---|---|---|
| `E-FSM-001` | ERROR | 状态机非法跃迁（当前状态收到了不允许的事件） | 记录事件与状态组合，场上继续运行；赛后对照状态图定位逻辑漏洞 |
| `E-FSM-002` | WARN | 状态机事件丢失（当前状态无法处理该事件，已丢弃） | 通常可忽略；频发说明事件产生与状态设计不匹配，赛后梳理 |
| `E-FSM-003` | ERROR | 状态机超时未流转（在当前状态停留超过预期时限） | 检查该状态的等待条件（传感器/通信）是否被上游错误阻塞 |
| `E-FSM-004` | FATAL | 状态机进入未定义状态（查表失败，已切入安全态） | 立即停机复位；这是严重逻辑缺陷，赛后必须复现修复 |

## SYS 域 — 系统资源域：内存、存储、CPU 节拍、日志设施自身的资源类事件

| 错误码 | 默认级别 | 中文含义 | 建议动作 |
|---|---|---|---|
| `E-SYS-001` | ERROR | 内存不足（分配失败或内存水位越限） | 记录发生时段与组件；场下配合 journalctl 查 OOM 记录（USAGE §7） |
| `E-SYS-002` | ERROR | 日志落盘失败（磁盘满/IO 错误，取证能力受损） | 检查存储剩余空间与 SD 卡健康；期间日志可能缺失，证据链降级 |
| `E-SYS-003` | WARN | 实时节拍超期（如 1kHz 节拍线程错过 deadline） | 记录超期时长；频发时检查是否有高负载任务抢占（配合 dmesg） |
| `E-SYS-004` | WARN | 存储水位告警（日志分区用量超阈值，即将依赖轮转清理） | 赛后及时导出并清理旧日志；确认轮转份数设置是否够用 |
| `E-SYS-005` | INFO | 系统里程碑事件（启动完成/优雅停机/配置切换等） | 无需处理；用于划定时间线（这是第几次上电、何时停机） |

## 扩展规则

1. 新增码只改 `rmlog/catalog.py` 的 `ERRORS` 表（域内序号延续现有最大值），
   然后重新执行 `python3 -m rmlog.gen_code`（生成 C 头）与
   `python3 -m rmlog.gen_code --doc`（生成本文档）；
2. 已发布码的语义与默认级别不得随意变更（C/Python 双端与读端工具都依赖它），
   确需变更时递增 `CATALOG_VERSION` 并同步 `USAGE.md`；
3. 新增域须同步 `catalog.py` 的 `DOMAINS`，生成器与读端工具自动跟随。
