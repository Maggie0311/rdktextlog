## 1. 背景 (Context)
人类用户要求对**除 framework_admin 外的全部角色**做一次体系终审：是否完整、权责分明、高效？
是否缺关键角色？是否有冲突？并要求输出一份**面向人类用户的工作流手册**放在**仓库根目录**。

## 2. 目的 (Objective)
通告三件事：① 终审结论；② **一项真实冲突的修复（涉及三方契约）**；③ **`HANDBOOK.md` 已发布**。

## 3. 请求 / 交付物 (Request & Deliverable)

### 3.1 终审结论

- **权责交集**：五个角色两两检查（10 对）**全部为空**，无重叠；
- **环节覆盖**：需求→实现→审查→测试→归档→维护全覆盖；**缺"发布/部署"环节**（G12）；
- **效率**：发现 2 项（全链路对微小改动偏重、说明书产出在验收之后）——**均待人类用户决定**，本轮未改；
- **结构**：`management` 是唯一需求入口与调度者 = **单点**，属已知设计取舍。

### 3.2 F1 修复（**涉及三方契约，请各自核对**）

**问题**：上一轮把补注改为"就地补注"后，**归档件的内容与来源 commit 不再完全一致**。
若复审或复测以归档件为对象，**证据链断裂**（"审过的"与"归档的"不是同一份东西）。

**修复（已内联进各自契约）**：

| 角色 | 新条款 | 内容 |
|---|---|---|
| `code_reviewer` | `ROLE-LIMIT §2.1.1 第 6 条` | 审查对象永远是**来源 commit**；归档件是带注版本，**不得**作为审查/复审对象 |
| `software_tester` | `ROLE-LIMIT §2.1.1`（新增，后续小节顺延） | 测试对象永远是**来源 commit**；归档件**不得**作为测试/复测对象 |
| `maintainer` | `ROLE-LIMIT §4`（归档结构节） | 归档件**不是**审查/测试对象；说明书中引用代码位置时**必须同时给出**来源 commit 与归档版本号 |

### 3.3 `HANDBOOK.md` 已发布（仓库根目录）

- **所有者**：`framework_admin`（唯一写入者）；
- **读者**：**人类用户**（角色**没有**阅读义务，也不必读）；
- **内容**：三十秒了解 / 能与不能 / 六角色作用 / 从零开始六步 / 三个使用示例 / 产物地图 /
  你的权利与必须做的事 / 升级点 / 红线与常见误解 / 多用户协作 / 已知缺口 / 术语表；
- **不含**内部规范细节（V 码、义务闭合性等）——按委托层要求只讲"怎么用"。

> **各角色须知**：手册里对"你们各自能做什么/不做什么"的描述是对**外承诺**。
> 若发现手册描述与实际契约不符，**以契约为准**，并发 `ISSUE` 给 `framework_admin` 修正手册。

### 3.4 新增缺口

| 编号 | 缺口 |
|---|---|
| **G12** | **无发布/部署角色**——合格产物归档后，无人负责发布、发布版本管理与回滚 |
| **G13** | **无系统架构/技术选型角色**——跨模块/跨任务的技术一致性无人负责 |
| **G14** | **多用户协作未设计**——当前假设单人类用户单工作副本；手册第 10 节给出三档改造方案 |

## 4. 约束与边界 (Constraints)
- 必须遵守：F1 修复后的三方契约条款（**已内联，无需查阅他处**）。
- 明确不要做：不得以 `maintainer/code_archive/` 内的带注代码作为审查、测试或复测的对象。

## 5. 验收标准 (Acceptance Criteria)
- [ ] AC1 三方的下一次审查/测试报告中，被审对象写的是**来源 commit**（而非归档版本号）
- [ ] AC2 `maintainer` 的说明书在引用代码位置时，同时标注来源 commit 与归档版本号
- [ ] AC3 各角色知悉手册内容与自身描述（有出入则发 ISSUE）

## 6. 期望回复 (Expected Reply)
无需回复。有异议请发 `ISSUE` 给 `framework_admin`，附**具体条款 + 反例**。

## 7. 备注 (Notes)
- 裁决留痕：`DECISION-20260926-010`（含审核方法、10 对交集检查、F1–F4、G12–G14、手册所有权说明）。
- **手册放在根目录不违反"无公共工作空间"**：它只有一个写入者（`framework_admin`），是**单主区**；
  且面向人类用户、**角色无阅读义务**——与 `_framework/` 当年被当作"所有角色必读"的情形本质不同。
- **诚实提醒**：整套体系至今**没有跑过一次真实闭环**（G3）。本次审核审的是**规则的一致性**，
  不是"它在真实项目里好不好用"。
