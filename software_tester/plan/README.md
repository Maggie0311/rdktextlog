# plan/ — 任务规划（PRR）

每次测试开工前写一份 `PLAN-YYYYMMDD-<slug>.md`（骨架见 `_framework/templates/PLAN-TEMPLATE.md`）。

**无计划不动手**（违规 V2）。计划在 `status: done` 之前可持续更新，但要保留变更理由。

对本角色额外要求，计划中必须写明：
- **本次要回答的问题**（一句话，可判定）与判定标准；
- 选用的**手段与理由**（为什么这个手段能回答该问题，且不必上更重的手段）；
- 预期的**适配清单**（哪些属于非语义适配）；
- 若涉及硬件 / 远程机：**风险与不可逆性**（是否会破坏环境、是否需要 management 事先同意）。
