# script/ — software_tester 的产物区

> 本目录是本角色的**交付产物区**，也是本角色唯一的写区。
> **本框架不存在公共工作空间**：产物只落在生产者自己的目录内。

## 1. 目录结构（本角色声明）

| 路径 | 内容 | 说明 |
|---|---|---|
| `script/ENVIRONMENTS.md` | **可用运行环境与工具链清单** | 每项标注 **已验证 / 假设 / 不可用**；只有「已验证」才可承诺 |
| `script/TESTPLAN-<task_id>.md` | 测试方案 | 首字段即"**要回答的问题**"+ 判定标准 |
| `script/TESTREPORT-<task_id>-<NNN>.md` | **运行结果报告** | 字段冻结见 `../role-limit/ROLE-LIMIT.md §4` |
| `script/work/<task_id>/` | **测试工作区** | 被测代码的**副本**、构建产物、原始日志、采集数据 |
| `script/dist/` | 复现包（可选） | `<task_id>-test.<ext>` |
| `script/INDEX.md` | 产物登记表 | 登记**交付单元**，不逐文件登记 |

## 2. 硬性约束（与本目录直接相关）

1. **只在 `script/work/<task_id>/` 的副本里构建与运行**——绝不进 `developer/` 目录构建（TN9）。
2. **原源码只读**：`developer/script/**` 一个字都不改（TN1）；为跑起来所做的**非语义适配**必须在报告中逐条声明（TN2 + §4 适配判定表）。
3. **证据不可丢**：`TESTREPORT-*` 与**原始输出**必须入库；工作区内的可重建产物（构建中间物、大体积副本）
   是否入库由本角色在 worklog 中声明，但**报告引用的原始输出不得只存在于被忽略的路径**。

## 3. 交付方式（跨角色流转，冻结）

发 `RESULT` 时给出：① **报告路径** ② 被测 **commit hash** ③ **复现命令** ④ 原始输出路径 ⑤ 可选复现包路径（写入 `attachments`）。
**跨角色推进一律经邮箱**；不得直接修改他方产物。
