# REQ-20261001-logging-v3-roadmap — logging 下一版开发规划（自动记录 + 场下秒定位）

> 定位：在 v1（地基）与 v2（异步/会话/自启/导出）之上，下一版补齐"自动记录"与"场下快速定位"的上半层。
> 本文融合两套方案（我方监控层方案 + 外部 AI 的黑匣子/捕获线方案），作为 M2 立项依据。
> 日期：2026-10-01 · 维护：management (R-002)

## 一、三层目标

| 目标 | 一句话 |
|---|---|
| 赛场自动记录 | 上电即记（自启 + 启动 Marker 含 git 版本/时间/电源状态），全程零操作 |
| 错误自动记录 | 三条捕获线 + 监控层，业务错误从"逐点打点"降到"喂狗 + 挂统计" |
| 场下快速定位 | 检索 + 统计 + 黑匣子回放——"知道错了，也知道错之前 2 秒在干什么" |

## 二、功能清单（按优先级）

**P0（灵魂，替代 Keil debug 的核心）**
1. **黑匣子环形缓冲** —— 内存环形缓冲持续存最近几秒高频数据（底盘指令/IMU/各状态机当前态/心跳计数），任何 ERROR/崩溃时连同上下文刷进日志文件（"飞行记录仪"）。
2. **signal 崩溃钩子** —— SIGSEGV/SIGABRT 写"遗言"最后一条 + 留 coredump（替代板端不可用的 coredumpctl）。

**P1（自动捕获线）**
3. **dmesg 监听进程** —— 后台监听内核日志，硬件错误实时转成业务错误码（与被动导出不同，是主动转码）。
4. **看门狗心跳 + systemd WatchdogSec** —— 主循环喂狗，超时自动记 FSM 卡死；systemd 兜底重启。
5. **通信错误率统计** —— SPI 层统一统计超时/重试，超阈值自动记 COMM 错误。
6. **资源越限监控线程** —— 温度/电压/内存越限自动记 HW/SYS 错误。

**P2（工程化）**
7. **错误码与下位机共用统一头文件** —— bit 编码（模块ID 8bit + 级别 4bit + 错误号 12bit），与 STM32/RT-Thread 下位机同源；配错误码手册 + 解码脚本。
8. **systemd 实装 + 启动 Marker 增强** —— 板端实测自启/重启；Marker 补 git 版本号 + 电源状态。
9. **检索脚本加统计 + 命中自动倒黑匣子** —— 频次/首末次统计；命中 ERROR 自动倒出错误前 N 秒快照。

**P3（远期）**
10. 异步写入性能优化 + 长跑稳定性验证。
11. SPI 从机日志回传收编。
12. CI/自动化测试 + 多车复用。

## 三、与 v1/v2 的关系（已实现，不重做）

- **v1 已实现**：行格式（墙上+单调两钟、级别、错误码、模块、消息）、五域错误码、C/Python 双端同源、多进程安全落盘+轮转、崩溃 flush、读端过滤。
- **v2 已实现**：异步非阻塞入队、会话标识、自启模板、一键证据导出、故障检测适配接口。
- **下一版只做 P0–P3**，不重做地基。

## 四、需用户拍板的 3 个决策点

1. **错误码编码形式**：现为字符串（`E-INIT-001`），外部方案建议 bit 编码（`0x2103`）与下位机共用——建议"字符串保留 + 新增 bit 编码映射层"双轨，避免破坏 v1/v2 兼容；是否采纳需用户定。
2. **黑匣子记录哪些高频数据**：需业务侧列出（底盘指令/IMU/各状态机态/心跳计数）。
3. **与下位机共用头文件落地方式**：需确认 STM32/RT-Thread 工程现状与跨端编码一致性。
