# from_human/ — 人类用户给 `management` 的文件入口

> **唯一写入者：人类用户。**
> `management` 对本目录**只读**——它**不会修改、移动或删除**你放的任何文件（其契约 MN14）。
> 想更新某个文件：**直接覆盖或另存新版本**，然后说一声即可。

## 1. 你可以放什么

任何你希望 `management` 在**拆解需求、做计划、做决策**时参考的东西：

- 需求文档、会议记录、任务说明；
- 接口说明、协议手册、芯片/板卡手册；
- 参考实现、样例代码、数据样例；
- 截图、图纸、表格、PDF。

> **一句话**：你口头不好说清的东西，放这里。

## 2. 怎么放（三步）

1. **把文件复制到本目录**（放这一层即可；想分组可以自建子目录）；
2. **建议**命名成 `<YYYYMMDD>-<简短说明>.<扩展名>`，例如 `20260927-串口协议手册.pdf` ——
   *只是建议，不强制*，你原来的文件名也完全可以；
3. 提需求时**带一句**："参考 `management/from_human/20260927-串口协议手册.pdf`"。
   **不带也行**：`management` 每次开工都会扫这个目录，只是带一句更快对上号。

## 3. `management` 会怎么处理

1. **开工时扫描本目录**并与 `INTAKE-LOG.md` 对比，找出它**还没处理过**的文件；
2. 读完在 `INTAKE-LOG.md` 追加一行：文件 / 收到时间 / 用在哪个需求或任务 / 备注；
3. 在需求拆解书（`script/REQ-*.md`）里**以路径引用你的文件**，而**不是复制内容**——
   这样永远以**你的原件**为准，不会出现"抄错了"的版本；
4. 若它读不懂或看出矛盾，会发信问你，而**不会**自己猜。

## 4. 与邮箱的区别（别混）

| | `management/from_human/`（本目录） | `management/mailbox/` |
|---|---|---|
| 放什么 | **你交给它的参考文件**（附件、资料） | **往来邮件**（任务、结果、问题） |
| 谁写 | **只有你** | 各角色按协议投递 |
| 用途 | 让需求有据可依 | 让协作可追溯 |

## 5. 注意事项

- **本目录不是"归档区"**：你放的文件会**一直保留**，`management` 不会替你清理；
- **大文件**（几十 MB 以上）建议不要直接放，改为告诉它文件在哪（路径或链接）；
- 若你发现自己的文件**被改动或消失** → **立即告知 `framework_admin`**：
  本目录的唯一写入者是你，任何角色改动它都属违规。
