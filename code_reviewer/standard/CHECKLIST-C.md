# CHECKLIST-C — C 语言专项检查清单（v1.0）

> 适用：`scope` 为 C 的交付。与 `CHECKLIST-COMMON.md` **同时**执行，不可替代。

## A. 内存与指针

- [ ] **C-01** 每个 `malloc / calloc / realloc` 的返回值都检查了吗？
- [ ] **C-02** 每个分配路径在**所有**出口（含错误路径、提前 `return`、`goto` 清理段）都有对应的 `free` 吗？
- [ ] **C-03** 是否存在 use-after-free / double-free？**所有权是否明确**（谁分配谁释放，是否跨函数转移）？
- [ ] **C-04** 指针是否可能在为 NULL 时被解引用？
- [ ] **C-05** 数组下标是否可能越界（含 off-by-one、负数下标、`size_t` 回绕）？
- [ ] **C-06** `ptr = realloc(ptr, n)` 反模式（失败时丢失原指针）是否出现？
- [ ] **C-07** 结构体是否在未初始化时被整体读取或 memcmp 比较（padding 未初始化）？

## B. 缓冲区与字符串

- [ ] **C-08** 是否使用了无界函数：`strcpy / strcat / sprintf / gets / scanf("%s")`？
- [ ] **C-09** `snprintf` 的返回值语义（截断检测）是否被正确处理？
- [ ] **C-10** 字符串是否可能未以 `'\0'` 结尾？`memcpy / strncpy` 之后是否补了终止符？
- [ ] **C-11** 缓冲区大小计算是否使用了正确的单位（字节 vs 元素数 vs 字符数）？
- [ ] **C-12** `sizeof(ptr)` 与 `sizeof(array)` 是否被混用（数组退化为指针）？

## C. 未定义行为与陷阱

- [ ] **C-13** 有符号整数溢出、移位超过位宽、负数移位？
- [ ] **C-14** 未对齐访问、strict aliasing 违规、类型双关（`*(int*)&f`）？
- [ ] **C-15** 序列点 / 求值顺序依赖（`i = i++`、同一表达式内多次副作用）？
- [ ] **C-16** 格式化字符串与参数类型是否匹配（`%d` 传 `long`、`%s` 传非字符串）？
- [ ] **C-17** 越界读写的"看似正确"写法（`buf[len] = 0` 在 len == 容量时）？

## D. 类型与转换

- [ ] **C-18** 隐式窄化转换是否丢数据（`size_t → int`、`long → short`）？
- [ ] **C-19** 有无符号混用比较（`if (x > 0u)` 当 x 为 `int` 且为负）？
- [ ] **C-20** `enum` / 位域的边界值与符号性是否被考虑？

## E. 并发与系统调用

- [ ] **C-21** `volatile` / 内存屏障 / 原子操作是否用在真正需要的地方（且没有滥用 `volatile` 当同步）？
- [ ] **C-22** 信号处理函数中是否调用了**非异步信号安全**函数（`printf / malloc` 等）？
- [ ] **C-23** 系统调用 / 库调用的返回值与 `errno` 是否被检查？是否处理了 `EINTR`？
- [ ] **C-24** 文件描述符 / socket / 线程是否在**所有路径**被关闭 / join？
- [ ] **C-25** 结构体跨进程 / 跨平台传输时的对齐与字节序是否被处理？
- [ ] **C-26** 静态缓冲区 / `static` 局部变量导致的**非可重入**问题？

## F. 构建与工具链

- [ ] **C-27** 是否能在 `-Wall -Wextra` 下干净编译？（有告警必须说明理由，不得默认忽略）
- [ ] **C-28** 是否存在仅在本机可编译的假设（隐式函数声明、缺失 include、依赖编译器扩展）？
- [ ] **C-29** 是否有平台相关的假设（字长、字节序、对齐、路径分隔符）？
- [ ] **C-30** 新增的源文件是否已加入构建系统（Makefile / CMake），而不是"本地能编过"？
