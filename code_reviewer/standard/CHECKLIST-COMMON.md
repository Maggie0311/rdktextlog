# CHECKLIST-COMMON — 通用检查清单（v1.0，语言无关）

> 每次审查**必须**完整过一遍本清单。编号用于报告中的"依据条款"字段。
> 用法：逐条自问"这一条在这份代码里成立吗？"——**"我没看到问题"不等于"已检查"**，两者要分开记。

## A. 需求与逻辑正确性

- [ ] **GEN-01** 实现是否逐条满足 AC？（逐条对照，不是"看起来相关"）
- [ ] **GEN-02** 所有分支是否可达且被正确区分？有无恒真 / 恒假条件、被短路跳过的分支？
- [ ] **GEN-03** 循环：起止条件、空集合、单元素、终止性（是否存在死循环 / 无限重试）？
- [ ] **GEN-04** 是否所有路径都有返回值？错误路径返回的值是否合理（而非默认假值）？
- [ ] **GEN-05** 有无复制粘贴后忘记修改的变量 / 分支 / 常量（copy-paste 错误）？
- [ ] **GEN-06** 数值：整数溢出、除零、浮点相等比较、单位换算、精度累积误差？
- [ ] **GEN-07** 时间：是否用墙钟测量间隔（应使用单调时钟）？超时、时区、夏令时是否处理？
- [ ] **GEN-08** 并发：共享状态是否有保护？是否存在锁顺序导致死锁、TOCTOU、竞态读改写？
- [ ] **GEN-09** 状态机：是否存在未定义的状态转移？异常路径是否把状态留在中间态？

## B. 错误处理

- [ ] **GEN-10** 每个可能失败的调用是否都检查了失败？
- [ ] **GEN-11** 失败后是否有明确的上报路径（返回值 / 日志 / 异常），而不是静默继续？
- [ ] **GEN-12** 错误信息是否足以定位问题（含上下文：哪个输入、哪个文件、哪个阶段）？
- [ ] **GEN-13** 是否存在吞掉异常 / 忽略返回值的写法？（**这是最常见的隐蔽缺陷来源**）
- [ ] **GEN-14** 部分失败时是否有回滚 / 清理？是否留下半完成状态？

## C. 资源管理

- [ ] **GEN-15** 每条资源获取路径（内存 / 文件 / 句柄 / 锁 / 连接 / 线程 / 临时文件）都有对应释放路径吗？**含错误路径与提前 return**。
- [ ] **GEN-16** 是否存在"反正进程很快退出，不释放也行"的假设？
- [ ] **GEN-17** 资源上限是否被考虑（无限累积的列表 / 缓存 / 日志）？

## D. 接口与契约

- [ ] **GEN-18** 函数的前置条件（入参范围 / 非空 / 长度 / 编码）是否被验证或明确记录？
- [ ] **GEN-19** 本次改动是否破坏既有调用方（签名 / 语义 / 返回值 / 副作用）？**是否搜索过全部调用点**？
- [ ] **GEN-20** 全局状态 / 单例 / 静态变量的修改是否会影响其他调用方？
- [ ] **GEN-21** 公开接口的行为是否与 `CODE-STYLE.md` 或既有文档一致？

## E. 安全

- [ ] **GEN-22** 外部输入是否被当作可信数据使用（缓冲区长度、路径拼接、命令拼接、反序列化、格式串）？
- [ ] **GEN-23** 是否有硬编码口令 / 密钥 / token / 内网地址？
- [ ] **GEN-24** 权限、路径穿越、符号链接、临时文件竞态是否被考虑？

## F. 可维护性（**仅在违反条款时才可要求返工**）

- [ ] **GEN-25** 命名是否表达意图？有无误导性命名（名字与行为不符）？
- [ ] **GEN-26** 注释是否与代码一致？是否存在**过期注释**（比没有注释更危险）？
- [ ] **GEN-27** 是否存在 3 处以上的复制粘贴重复逻辑？
- [ ] **GEN-28** 是否有死代码 / 被注释掉的代码 / 调试输出残留？
- [ ] **GEN-29** 嵌套深度是否过深（>4 层）导致不可读？
- [ ] **GEN-30** 魔法数字 / 硬编码常量是否被命名或说明来源？

## G. 可验证性（对抗"懒惰批准"）

- [ ] **GEN-31** 交付声称的验证证据能否被**独立复现**（命令、输入、输出）？
- [ ] **GEN-32** 边界用例是否被**实际运行**过，而不只是"逻辑上应该对"？
- [ ] **GEN-33** `IMPL` 中的"未覆盖项 / 已知风险"是否诚实列出，还是被含糊带过？
- [ ] **GEN-34** 交付的改动范围是否等于任务范围（有无夹带的范围外修改）？
