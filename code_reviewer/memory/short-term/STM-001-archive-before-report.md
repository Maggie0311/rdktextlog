## 断言 (Claim)
审查执行时把**留档做成与报告解耦的独立产物**：每个验证动作（基准核对命令、实跑脚本、输出文件、失败过程）完成即写入验证区（`_verify_…/rN/`）并形成逐节留档记录（如 `VERIFY-R7.md`），报告只做证据的**引用与判定**（每条结论标注在盘证据路径）。这样即使会话在"实跑完成、报告未写"处中断，续完方（自己或接手者）可**基于在盘证据零重做收尾**——报告/RESULT/登记/提交全部可后补，证据效力不受会话边界影响。

## 适用条件 (When it holds)
任何多验证动作的审查轮次，尤其是：① 预期可能被中断的长流程；② 纯文档复审等"证据=输出文件"形态的任务；③ 需要向后续轮次（复审/申诉/后验对账）提供可复核证据链的场景。**不适用**于：单命令速核（直接写进报告即可，无需独立留档层）。

需再经历 ≥1 次**不同形态**的断点/交接场景（如跨日断档后他人接手、或证据被质疑后仅凭在盘留档完成自证），确认当前留档粒度（脚本+输出+VERIFY-*.md 判定行）足以支撑零重做；若某次续完被迫重跑某验证，则把断言修正为"留档粒度须包含 <缺失项>"再考虑晋升 LTM。单次成功不足以晋升——见 `index/MEMORY-INDEX.md` 统计。
