# STM-000 — 短期记忆初始化

> 本文件仅用于说明短期记忆的初始化状态，**不构成一条经验**。真实条目从 STM-001 起。

| 字段 | 值 |
|---|---|
| 初始条目数 | 0（依据记忆模型 §4.1：无任务即无经验，禁止硬凑） |
| 建库时间 | 2026-09-23 |
| 当前条目 | 无 |
| 容量上限 | 12 |
| 容量策略 | 超出时优先丢弃 `confidence` 最低且 `salience: low` 的条目 |

短期记忆不是"发现了多少 bug 的流水"（那是 `script/REVIEW-STATS.md` 与 `REVIEW-*.md` 的职责）。
它是**从审查中提炼出来、尚待验证的审查方法论**。写入前三问：

1. 这条经验在**下一个不同的交付**里还能用吗？
2. 它能被证伪吗？（"这样审比较靠谱"不行）
3. 它有具体证据吗？（哪个 `task_id`、被谁确认过）

三问有一问为"否" -> 不写。

**合格示例**（尚未发生）："错误路径的资源释放必须逐条推演，抽样审查在此类路径上漏检率明显偏高；
依据 T-2026-09-24-001 复审时被 developer 指出的漏项。"
**不合格示例**："今天审得很仔细" —— 无法证伪，且对未来审查无指导。
