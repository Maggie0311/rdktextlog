## 5. 五项处置逐条核销（以本角色验证为准）

### 处置 1【硬错误】构建可移植性 —— 源码内定义特性测试宏 —— **成立**

- **宏位置**（rmlog.c:56-58）: `#if !defined(_WIN32) / #define _POSIX_C_SOURCE 200809L / #endif` 位于**任何 `#include` 之前**（本文件首个 `#include "rmlog.h"` 在 :60；rmlog.h 内含 `<stddef.h>`，其 glibc 实现首行即 `<features.h>`，故宏在 `<features.h>` 被首次拉入前已生效）。✓
- **`_WIN32` 分支不受影响**: 宏被 `#if !defined(_WIN32)` 守卫，Windows/MinGW 下不定义（MinGW 无 `<features.h>`，该宏无意义且会干扰 MSVCRT 头，正确回避）。✓
- **200809L 覆盖所需符号**（POSIX 标准事实 + glibc 特性宏阈值）:
  - `clock_gettime` / `CLOCK_MONOTONIC` —— POSIX.1b-1993（Realtime 扩展，后并入 POSIX.1-2001 基础），glibc 在 `_POSIX_C_SOURCE >= 199309L` 时声明；
  - `localtime_r` —— POSIX.1c-1995（线程安全函数，后并入 POSIX.1-2001），glibc 在 `_POSIX_C_SOURCE >= 199506L` 时声明；
  - `fdatasync` —— POSIX.1b-1993，glibc 在 `_POSIX_C_SOURCE >= 199309L` 时声明。
  三者阈值均 ≤ 199506L，`200809L`（POSIX.1-2008）**全覆盖**。且 tester 板端边界表征（`q4_char_c99_POSIX.txt`）已证 `-D_POSIX_C_SOURCE=200809L` 硬错误清零、仅余 3× format-truncation —— 源码内 `#define` 与该 `-D` 在"任何 glibc 头之前定义"语义上**等价**，故板端背书成立。
- **宏冲突**: rmlog.h 不含 `_POSIX_C_SOURCE`（仅 `stddef.h` + `rmlog_errors.h`），无冲突；宏定义在包含关系最上游，不会被子头文件覆盖。
- **取舍（任务书要求"二选一并说明理由"）**: 选特性测试宏而非 `-std=gnu99`，理由（①精确覆盖缺失符号 ②保持严格 ISO C99 ③文档命令 `-std=c99` 原样可编译不改文档 ④tester 边界表征背书）**逐条成立**，且实测文档命令 `-std=c99` 双平台可编译（W2/W4）。

### 处置 2【警告】3× `-Wformat-truncation` —— 根上消除（非 `-Wno` 压制）—— **成立，可证安全**

- **三处告警定位**（对照板端原始证据 `q1_selftest_raw.txt` / `q4_compile_raw.txt`，旧行号 443/436/437 = 新行号 473/466/467）: 全部落在 `rmlog__rotate_chain_locked` 的**轮转副本路径**拼接 `snprintf(src,"%s.%d")` / `snprintf(dst,"%s.%d")` / `snprintf(dst,"%s.1")`，与 developer 声称一致。

### 7.1 提示级发现项（NIT，不要求返工，不影响 PASS）

**NIT-1【提示】`_POSIX_C_SOURCE` 未用 `#ifndef` 保护**（rmlog.c:56-58）

- **位置**: `rmlog/rmlog.c:56-58`
- **现象**: `#define _POSIX_C_SOURCE 200809L` 无条件定义（仅外层 `#if !defined(_WIN32)`），未用 `#ifndef _POSIX_C_SOURCE` 保护。
- **复现路径/推演链**: 若使用者在命令行另行传 `-D_POSIX_C_SOURCE=<其他值>`（如构建系统全局 `-D_POSIX_C_SOURCE=199309L`），编译时源码内重定义为 200809L，gcc 报 `warning: "_POSIX_C_SOURCE" redefined`（值不同即告警；值相同如 200809L 则静默）。文档化命令 `-std=c99` 不含 `-D`，故**正常路径无此告警**；该场景为文档明确"无需 `-D`"后的矛盾用法。
- **依据条款**: 无 `CODE-STYLE.md`/标准明示条款要求 `#ifndef` 保护（SEVERITY §2"找不到条款依据 → 最高 NIT"）。
- **级别 + 建议**: NIT（提示），**不要求返工、不影响本轮 PASS**。若后续需兼容"构建系统统一传 `-D_POSIX_C_SOURCE`"的形态，可改为 `#if !defined(_WIN32) && !defined(_POSIX_C_SOURCE)` 再定义；属可选项，由 developer 视接入形态决定，无需本轮处理。
