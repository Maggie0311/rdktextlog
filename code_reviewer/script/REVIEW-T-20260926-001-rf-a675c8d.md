- **现象**: 每次经该函数**成功执行一次打开**（close 后的按需重开、`rmlog_open(NULL)` 的成功打开）即泄漏 1 个文件句柄（POSIX fd / Win32 HANDLE 双端同构），失败路径不泄漏（与 W5 实测的 1:1 增量吻合）。其余行为碰巧正确: 首次 open 若失败，:175 同路径同 flags 的第二次 open 必然同样失败 → 返回 -1，与"单次 open"语义等价——这正是 `-Wall -Wextra` 无法告警、selftest 12/12 仍全绿的原因（正确性路径无恙，纯粹是资源泄漏）；成功时两 fd 指向同一文件，O_APPEND 下数据仍完整，故**任何数据正确性用例都测不出**。长期后果: 句柄/描述符持续累积 → 触达进程配额后进程级资源获取开始失败，日志以"打开失败计数增长"的隐蔽方式停记（rmlog.c:514-517），业务侧其他文件操作亦可被拖累。

- **依据条款**: `CHECKLIST-COMMON.md` **GEN-15**（每条资源获取路径都有对应释放路径——本条为成功路径上的获取无释放）、**GEN-13/GEN-10**（首个 open 的返回值被无条件覆盖，属"忽视调用结果的隐蔽缺陷"形态）、**GEN-02**（分支结构冗余/不可达结构）；R2 diff 头注释自述修复面为"一个函数内的分支前置"，与实际结构（分支内打开 + 尾部再打开）不符（GEN-26 关联）。`SEVERITY.md` §1 MAJOR（特定但现实的条件下出错——rmlog.h 记载的合法用法上确定发生、慢性累积至故障）。
