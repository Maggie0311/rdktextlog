## 1. 目标 (Objective)
创建 R-006 `maintainer`（代码维护者）：接收经 `developer` 与 `software_tester` **多轮测试确认合格**的代码产物，
**冻结归档**（`code_archive/` 版本化系统）、**深度理解并生成给人看的简洁说明书**、
**在不改代码语义的前提下为人类补注**、并**回答人类关于代码细节与含义的任何提问**，
服务于人类的**长期维护、审查与最终裁决验收**。

可验收判据：① 与既有五角色"只能做"交集为空（尤其与 R-004 静态审查、R-005 动态测试）；
② 归档件的原产物**字节可校验**且不可变；③ 说明书能让人**只读它就知道代码结构与各部分功能**；
④ 全流程不修改任何来源产物。

## 2. 事实 (Facts)
1. 现有角色：R-001 治理 / R-002 调度 / R-003 生产 / R-004 静态审查 / R-005 动态测试。**无"归档与长期可维护性"角色**。
2. 委托层原话要点：提取**合格产物**；深度理解剖析；生成**简洁说明文件**使人类**精确理解结构与各部分功能**；
   **不修改源代码**下**适当补充注释**；**各版本归档**（特殊文件夹 `code_archive`，**与 mailbox 的 archive 区分**）；
   回答**任何**代码细节与含义的提问；支撑**最终裁决与验收**；满足**长期维护**；维护可读性、更改、核心思路，**能教人类理解代码**。
3. 委托层另要求：**让 developer 与 software_tester 确定合格后通知 maintainer**；介绍给现有角色；注入记忆；
   其余功能**用选项框交互确认**。

### 2.1 关于选项框（诚实记录）
framework_admin 于本轮发起 `ask_user_question`（6 个问题：归档触发 / 补注方式 / `code_archive` 位置 /
归档粒度 / 疑点去向 / 附加产物多选），**调用超时（10 分钟无响应）**。
为避免空转，采取以下处理：
- **核心功能**（委托层已明确的四项：说明书 / 补注 / 归档 / 答疑）按原话**直接落地**，不需要选择；
- **六项待定设计**按 **framework_admin 的推荐默认值**落地，并在本文件与最终回复中**显著标注"待确认"**；
- 委托层确认后如需调整，**以小改动的形式修订**（契约升版 + NOTIFY），不影响本轮主体交付。

## 3. 待定项的默认取值（**待委托层确认**）

| # | 待定项 | 采用的默认值 | 理由 |
|---|---|---|---|
| 1 | 归档触发 | **developer 与 software_tester 两封通知齐备**后归档；management 验收结论**事后回填**版本卡 | 委托层明确"两者确定合格后通知"；回填使归档能反向支撑人类最终裁决 |
| 2 | 补注方式 | **原产物按字节冻结归档 + 另存带注副本** | 既满足"不修改源代码"，又满足"补充注释供人类阅读"；保住 commit hash 与审查/测试证据的对应关系 |
| 3 | `code_archive` 位置 | `maintainer/code_archive/`（角色目录内） | 符合 §2.1 无公共工作空间；与 `mailbox/archive` 天然区分 |
| 4 | 归档粒度 | **全留历史**；未采用版本留墓碑记录；**大文件不入库**（存校验值与重建方式） | 长期维护需要演进过程；避免仓库膨胀 |
| 5 | 疑点去向 | **发 ISSUE 给 developer 并抄 management**，只报告、不修码、不裁定 | 深度理解必然发现问题，不许报告等于知情不报；但修复与判定仍归他人 |
| 6 | 附加产物 | 先不产出附加物，**保留接口**（走读 / 术语表 / 版本差异 / 关键问题清单只需在 `SPEC` 中加节） | 待委托层勾选后再补，避免一次堆砌 |

## 6. 风险与回滚 (Risk & Rollback)

| 风险 | 概率 | 影响 | 缓解 | 回滚动作 |
|---|---|---|---|---|
| **给出错误但可信的解释**（比不解释更坏：人类据此维护与裁决） | 中 | **极高** | 说明书强制**区分事实层与推断层**；关键结论必须给 `file:line`；不确定标 `unverified`；禁止"凭印象解释" | 修订说明书 + 记更正条目 |
| 补注被扩展到代码行（等于改了源码） | 中 | 高 | 补注判定表：**只允许新增注释**；带注副本与原件的 diff 必须**只有新增注释行**；审计可查 | 废弃带注副本并重做 |
| 归档件被"顺手更新"（破坏冻结性） | 中 | 高 | `original/` 写入即冻结；改动只能新增版本；版本卡记 SHA-256 | 记更正 + 从来源重新归档 |
| `code_archive` 与 `mailbox/archive` 混用 | 低 | 中 | 两者写入规则与命名完全不同；`code_archive/README.md` 首节即写明区别 | 重排目录 |
| 与 R-004 / R-005 职责重叠（都在读代码） | 中 | 中 | 以**产出物的性质**切分：判断 / 事实 / **解释** | 重裁并升版契约 |
