## 1. 目标 (Objective)
依人类用户指令，**废止 `src/` 产物区设计**，把交付产物落回**各角色自己的 `script/`**，
使框架回到它自己已经声明的定义（`00-ARCHITECTURE §2`：`script/` = 产物）。

可验收判据：全仓不再存在把 `src/` 作为**规定**的文本；`developer` 与 `code_reviewer` 的契约、原则、标准、记忆、任命信
全部指向 `<role>/script/`；根约定与裁决留痕可追（历史结论不重写，用新裁决替代）。

## 2. 事实 (Facts，先核查后动手)
1. `src/` **从未被创建**（`Test-Path src` = False），无任何代码产物——**零迁移成本**。
2. 全仓 `src/` 引用共 **40 处**，分布约 20 个文件。
3. 用户判定：产物写在角色自己的 `script/` 内，更符合"每个角色一个文件夹"的定义；交付时打包、经邮件发给其他角色推进下一步。

## 3. 我的评估（不掩饰）
`src/` **不是"不切实际"，而是与框架自身的定义相矛盾**：
- `00-ARCHITECTURE §2/§3` 已定义 `script/` = "我**产出**了什么可用东西"；代码正是可复现资产；
- 我却在角色目录之外另立产物区，还为此写了一整套"跨角色共享写入区"规则（`05-CONVENTIONS §7.1`），
  凭空增加了一个需要额外维护的共享面。
**结论：该设计应当废止。** 用户指出的是真实缺陷，不是口味差异。
