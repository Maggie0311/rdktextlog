## 1. 目标 (Objective)
创建 R-005 `software_tester`（软件测试工程师）：接收 `management` 的分配与 `developer` 的代码，
**仅在需要时**用恰当手段让程序在正确的平台上跑起来，采集运行反馈并**科学地**汇报结果；
**不得修改 developer 的源代码、也不得为测试而修改程序**。

可验收判据：① 该角色的"只能做"与 R-003（写代码）、R-004（静态审查）、R-002（验收）**交集为空**；
② 它能在**不改程序**的前提下完成"复制→构建→运行→采集→报告"的完整闭环，或如实报告"环境不可得"；
③ 其产物落在**自身目录内**（架构 §2.1），交付经邮箱。

## 2. 约束 (Constraints)
- 本角色硬边界：只做角色定义 / 边界 / 规范 / 任命（A1、A2、A6），**不代做业务产出**（N1）。
- 用户口述硬需求：接收 management 分配；手段包括但不限于——本机特定位置建副本直接测、烧录单片机、
  经串口等在其他计算机上复制并测试、分析并汇报结果；**环境由它决定与适配**；**必须有读取运行反馈的能力**；
  **不得直接修改程序进行测试，也不得修改 developer 的源代码**；本质是"把源代码本身加以运用和测试"。
- 已生效约束：`00-ARCHITECTURE v1.2 §2.1`（角色自足、无公共工作空间）、`§4.1`（审查门）、
  `05-CONVENTIONS v1.2 §7`（产物区 = 各自 `script/`、提交隔离）。

## 4. 专业方法 (Method)
1. **以"产出的性质"切分与相邻角色的边界**（沿用已验证的 STM-004 / STM-006 方法）：
   - R-003 产出**代码**；R-004 产出**静态判断**；R-002 产出**验收决定**；
   - R-005 产出**运行事实与证据**（"跑起来是什么结果"）。
   四者问题不同、产物不同、目录不同 → 交集为空。
2. **把"不能改程序"落成可判定规则**：区分**非语义适配**（允许：构建/链接参数、设备与端口配置、部署外部依赖、物理条件）
   与**语义改动**（禁止：改逻辑/常量/接口/加桩替换真实模块/注释掉失败分支）。
   副本机制满足"建 copy 测试"的要求，同时保证原源码只读。
3. **把"科学汇报"落成字段冻结**：环境 / 副本来源 commit hash / 步骤 / 原始输出 / 复现性 / 覆盖声明（测了哪些角度、**没测什么**、为什么）。
4. **诚实优先于"能测"**：环境不可得时如实报告并升级，**禁止伪造运行结果**（本轮为此新增违规码 V8）。
