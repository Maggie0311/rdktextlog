## 1. 事实 (Facts)
1. `_framework/` 位于 `framework_admin/_framework/`（**由委托层从仓库根移入**；此前由我在根目录创建）。
2. 非 framework_admin 目录内累计 **151 处引用，分布 4 个角色、57 个文件**；按功能分类：
   **要求对方去读的义务型 32 处**、权限/禁令声明 13 处、溯源类 106 处。
3. 直接后果：四个角色的**行为义务有一半散落在 framework_admin 的目录里**——与其自身契约应当"自足"这一点相矛盾；
   且四封任命信都写着"读完 `_framework/` 六份根规范"，把阅读负担强加给新角色。

## 2. 决定 (Decision)：采用**方案丁**（甲 + 制度化）

### 2.1 `_framework/` 正式定性为**内部档案**（§2.1.2）
- 内容：立法底稿 + 角色登记与图纸 + 裁决与审计 + 模板；**唯一写入者** framework_admin；
- 其他角色对它**保留只读权限**（用于溯源），但**没有阅读义务**；
- 对角色生效的方式是**签发**（写进其契约），**不是引用**；
- 若档案与某角色契约不一致，**以该角色契约为准**，并由 framework_admin 修正档案。

### 2.2 新增不变量：**义务闭合性**（§2.1.1）
> **任何角色的行为义务，必须能在其自身目录内闭合。**
> 判据：指着某角色的目录问"**只读它自己的目录，能否知道该怎么做？**"——不能即为违规设计。
> 引用只允许用于**溯源**；溯源引用不得是理解义务的必经路径。
> **不禁止**跨目录只读访问（审查/验收/审计需要），禁止的是"把他方目录当作自己义务的来源"。

### 2.3 逐条内联（本轮实际执行）

| 内联内容 | 落点 |
|---|---|
| 邮件命名、12 个 front matter 字段、7 段正文、`purpose` 语义与**本角色义务** | 各角色 `mailbox/README.md` |
| 记忆条目字段、置信度初始值/更新/区间/**晋升 5 条件**/衰减与遗忘/短期容量 | 各角色 `memory/README.md` |
| 日志格式与"只追加"规则 | 各角色 `worklog/README.md` |
| 计划骨架（表头 + 九节） | 各角色 `plan/README.md` |
| 产物区范围、交付四要素（路径 + commit hash + 可复现命令 + 打包件） | 各角色 `script/README.md` |
| **提交隔离全文**（禁止盲加 / 提交前 `git status` / 他方未提交改动不得处理 / 一次一提交 / 历史不改写） | 各角色 `role-limit` §2.1 |
| **审查门**：交付方一侧（先审查再报 RESULT、逐条回应、代码变即失效） | `developer/role-limit` §2.1.1 |
| **审查门**：审查方一侧（结论独立于指令、用户书面例外、commit 绑定、结论≠验收） | `code_reviewer/role-limit` §2.1.1 |
| **审查门**：验收方一侧（缺报告或报告未通过不得判 `accepted`、唯一例外与备案） | `management/role-limit` §2.1.2 |
| 产物自足、接口冻结、伪造证据红线与后果 | 各角色 `role-limit` §2.1 |
| `上游依据` 行改为"**仅供溯源，不必阅读**" + 新增「**自足声明**」行 | 四角色 `role-limit` |
| 记忆溯源改写（"来自 `_framework/` 根规范" → "来自本角色契约的强制约束"） | 各角色 `LTM-000`、`CONSOLIDATION-LOG`、相关 LTM 证据行 |
