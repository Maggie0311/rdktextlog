## 1. 事实 (Facts)
1. 现有角色：R-001（治理）、R-002（调度）、R-003（生产）、R-004（静态审查）。
2. 用户要求新增 R-005，其能力范围是**让程序在真实平台上运行并取回反馈**。
3. **这是一种此前完全没有角色覆盖的能力**：R-003 只写代码、R-004 只做**静态**审查（读代码、不运行）。
   → 本轮识别出一条**运行验证真空**（此前未被登记），由 R-005 填补。
4. 用户给出的硬边界：不得修改程序进行测试、不得修改 developer 源码；且**"仅在需要的时候"**测试。
5. 本轮产出：`software_tester/` 35+ 文件（含 `script/ENVIRONMENTS.md` 骨架）、根规范 `00-ARCHITECTURE.md v1.3`（新增 V8）、本文件。

## 2. 决定 (Decision)
1. **采纳** R-005 `software_tester`（中文名"软件测试工程师"），active，生效 2026-09-25；目录位于仓库根，与 `framework_admin/` 同级。
2. **确立两条独立验证通道**：

| 通道 | 角色 | 回答的问题 | 手段 | 产出 |
|---|---|---|---|---|
| **静态审查** | R-004 `code_reviewer` | 代码在标准下**有没有问题** | 读代码、按清单逐项核对 | 审查报告（判断） |
| **动态运行** | R-005 `software_tester` | 程序实际跑起来**是什么结果** | 构建、运行、烧录、串口、远程机 | 运行结果报告（事实） |

   **两者互不替代、互不指挥、互不判定验收**；且**都不得修改代码**（R-004 的 RN1、R-005 的 TN1）。
3. **R-005 的权力轴（约束性裁定）**：
   - **服从**：要不要测、测什么、何时测（WHAT / WHEN，由 `management` 分配；"仅在需要时"由它判定）；
   - **自主**：环境选择与适配、测试手段、采集方式（HOW）；
   - **独立**：运行结果只受证据影响，不受任何指令影响；
   - **禁止**：修改被审代码（TN1）、为测试改动程序语义（TN2）、伪造证据（TN3/TN4）、宣布验收（TN5）、静态裁定（TN6）。
4. **"不能改程序"落成可判定规则**：`ROLE-LIMIT §4` 的**适配判定表**——
   **非语义适配**（编译/链接参数、设备与端口配置、路径、环境变量、外部依赖部署、物理条件）**允许但须逐条声明**；
   **语义改动**（改逻辑/常量/接口、加桩、注释掉失败分支、放宽断言）**禁止**，必须发 `ISSUE` 由 `management` 裁定，
   必要时由 `developer` 在新 `task_id` 下提供测试挂钩。
   这样既满足用户"可建副本测试"的要求，又保证**跑的是同一个程序**。
5. **根规范新增违规码 V8 伪造证据**（`00-ARCHITECTURE.md v1.3 §7`）：
   编造、篡改或**选择性呈现**用于支撑结论的证据。理由：本角色的全部价值在证据可信，
   而 V1–V7 中**没有一条**覆盖"证据造假"，这是框架级空缺。
6. **测试不是默认强制门**：是否测试由 `management` 决定（与 §4.1 审查门不同——审查门是强制的）。
   但**一旦决定测试，结果必须如实上报**。
7. **产物与能力清单**：测试产物落在 `software_tester/script/`（工作区副本在其 `work/<task_id>/` 内，符合 §2.1）；
   `script/ENVIRONMENTS.md` 记录可用环境与工具链，**每项必须标注"已验证 / 假设 / 不可用"**，只有"已验证"可承诺。

## 3. 冲突面裁定表（唯一主责）

| # | 候选动作 | management | code_reviewer | developer | software_tester | 裁定 |

> **第 2 与第 3 行的分离是本轮的关键一刀**：静态审查与动态运行是**两个不同的问题、两套不同的证据、两种不同的手段**，
> 合并会让"没发现问题"与"跑起来没问题"互相冒充。

## 4. 正交性与覆盖检查 (Orthogonality & Coverage)

**交集检查**（五角色两两，重点三对）：
- R-003（写）∩ R-005（跑）= **∅**：一个只有写权、一个只有读权与运行权；**且 R-005 明令不得改代码**。
- R-004（静态）∩ R-005（动态）= **∅**：问题、手段、产物、目录均不同；二者**互不替代**。
- R-002（验收）∩ R-005（运行）= **∅**：R-005 只给事实，验收决定归 R-002。
- R-001 ∩ R-005 = ∅（治理权与运行权不同域）。

**覆盖检查**：
| 环节 | 主责 |
|---|---|
| 需求 / 拆解 / 分派 / 追踪 / 验收 | R-002 |
| 代码实现 | R-003 |
| 静态审查 | R-004 |
| **运行验证（新识别出的真空）** | **R-005 —— 本轮填补** |
| 角色 / 边界 / 规范 / 任命 / 仲裁 / 审计 | R-001 |
