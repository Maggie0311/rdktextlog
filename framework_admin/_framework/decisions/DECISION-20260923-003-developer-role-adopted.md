## 1. 事实 (Facts)
1. 现有角色：R-001 `framework_admin`（治理层）、R-002 `management`（执行层·调度）。**无任何执行层·生产者角色**（缺口 G4）。
2. 用户要求新增 R-003 `developer`：与 R-001 平行同级，**服从 R-002 统领**，职责为编写软件代码；
   质量硬要求三项：结构清晰便于维护 / 风格规范 / **详细中文注释**；能力声明：C、Python 及其他语言。
3. 用户口述中首次出现"**同级于 A、服从于 B**"的混合关系——框架此前只有"平行同级、无指挥链"一种关系，**没有指挥链规则**。
4. 复核发现跨角色隐患：三个角色即将共用同一 git 仓库，而根规范**没有任何提交隔离条款**；
   `framework_admin` 自身已连续三次使用 `git add -A`（WORKLOG #15/#20/#22），当时仅因恰无他方未提交改动而未造成损失。
5. 本轮产出：`developer/` 34 文件（含任命信与 v1.1 通告信）、注册表三层结构声明、根规范 v1.1（两份）、本文件、两封邮件。

## 2. 决定 (Decision)
1. **采纳** R-003 `developer`（中文名"开发工程师"），active，生效 2026-09-23。
2. **框架中第一条真实指挥链成立：R-002 → R-003。** 其**范围被严格限定**（见第 3 节第 3 项）。
   "与 R-001 平行同级"指**治理关系**（R-001 不指挥 R-003，R-003 不参与角色与规范）；
   "服从 R-002"指**执行关系**（任务编排）。两者不矛盾：**同级 ≠ 无协作，服从 ≠ 无边界**。
3. **服从范围 = WHAT / WHEN；HOW 自主**（**约束性裁定，management 必须执行**）：
   - 服从：做什么、何时交、要满足哪些 AC、按哪个 `task_id` 追踪；
   - 自主：实现结构、算法、语言特性、代码风格、测试方式；
   - 理由：`management` 无技术专业身份，其自身契约 MN2 已禁止其做业务判断，P3 亦要求"按边界路由而非按便利"；
     若允许其指定实现，等于让**无专业判断权的一方做专业决策**，是双头决策的另一种形态。
   - 争议处理：`management` 若认为必须指定实现方式，须以**书面形式**（邮件 + 台账"路由理由"）给出裁定；
     `developer` 可发 ISSUE 附风险 / 证据 / 替代方案申辩；涉及不可逆损害（数据、安全）时升级人类用户。
4. **确立 `src/` 为项目源码产物区**，`developer` 为唯一写入者；其余角色只读。
   测试目录由 `developer` 在 `CODE-STYLE.md` 中声明，一经声明即受同等约束。
5. **根规范升级至 v1.1**（即刻生效，无破坏性变更、无需兼容期）：
   - `05-CONVENTIONS.md §7` 共享仓库与产物区（含 §7.2 提交隔离，**闭合新发现隐患**）；
   - `02-MAILBOX-PROTOCOL.md §2.1` 常驻信例外（**闭合缺口 G1**）。
6. **风格内容的归属分层**：framework_admin 只规定"**必须有、必须一致、必须可被检查**"；**具体风格内容由 `developer` 定**
   （`CODE-STYLE.md`）。依据本角色 N7：不替角色做业务/技术判断。

## 6. 澄清与自我更正：DECISION-20260923-002 §6 的"只读"范围

`DECISION-20260923-002 §6` 曾声明"`management/` 目录对 framework_admin 转为只读"。
本轮发现该表述若按字面执行，将**禁止我向 `management` 的 `inbox/` 投递任何邮件**（含本轮的 v1.1 通告与后续仲裁通知），
从而使**邮箱这一唯一正式通道被切断**——与本角色 A6 及架构 §6.4 直接冲突。**判定为表述缺陷，现予澄清（非推翻）：**

> "只读"的准确范围 = **R-002 的自身产物**：`memory/`、`script/`、`plan/`、`worklog/`、`outbox/`、`role-limit/`、`principles/`。
> **`mailbox/inbox/` 的投递权始终保留**——它是协议赋予的角色间唯一正式通道，也是我执行任命（A6）与仲裁通知（A7）的手段。
> 除投递外，对 R-002 目录**不得写入、不得修改**。

**更正方式**：本条为**新增澄清**，不修改 DECISION-002 正文（历史结论不改写，符合 `05-CONVENTIONS §4` 的不可变性精神），
变更以本条为准。此处理亦符合本角色升级路径中"发现自己定的规范自相矛盾 → 立即发 NOTIFY 更正"的要求。
