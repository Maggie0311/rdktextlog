## 1. 审核范围与方法

- **范围**：R-002 `management`、R-003 `developer`、R-004 `code_reviewer`、R-005 `software_tester`、R-006 `maintainer`（共 5 个角色）+ 根规范 + 角色间交互。
- **方法**：① 五角色两两"只能做"交集检查（10 对）；② 软件生命周期环节覆盖检查；③ **证据链连续性检查**（这次新增的检查维度，发现 F1）；④ 效率与瓶颈检查；⑤ 缺口核查（对照委托层原始要求）。

## 2. 审核结论

### 2.1 权责交集：**无重叠**（10 对逐对通过）

| 对 | 切分依据 | 结论 |
|---|---|---|
| management ↔ developer | **WHAT/WHEN vs HOW** | 空 |
| management ↔ code_reviewer | **验收 vs 静态判断** | 空 |
| management ↔ software_tester | **要不要测 vs 怎么测** | 空 |
| management ↔ maintainer | **验收许可 vs 归档执行** | 空 |
| developer ↔ code_reviewer | **写 vs 判** | 空 |
| developer ↔ software_tester | **写 vs 跑** | 空 |
| developer ↔ maintainer | **来源只读** | 空 |
| code_reviewer ↔ software_tester | **静态判断 vs 动态事实** | 空 |
| code_reviewer ↔ maintainer | **判"对不对" vs 讲"是什么"** | 空 |
| software_tester ↔ maintainer | **跑 vs 解释** | 空 |

**特别说明（三读码角色）**：`code_reviewer` / `software_tester` / `maintainer` 都会读同一份代码，
但**读码目的不同**（判断 / 运行 / 解释），产出物性质不同，故不构成重叠。

## 3. 委托层要求的「根目录手册」

- **产物**：`HANDBOOK.md`（仓库根目录，与各角色文件夹同级）
- **所有者**：`framework_admin`（**唯一写入者**）
- **内容**：三十秒了解 / 能做什么与不做什么 / 六角色各自作用与交互方式 / 从零开始六步 / 三个使用示例 /
  产物地图 / 你的权利与必须做的事 / 升级点 / 红线与常见误解 / **多用户协作** / 已知缺口 / 术语表
- **不含**：内部规范细节（V 码、义务闭合性等），按委托层要求只讲"怎么用"

### 3.1 关于"手册放在根目录"与 §2.1 的关系（必须说明）

§2.1 规定"不存在公共工作空间、每块区域只有一个写入者"。`HANDBOOK.md` 位于根目录、**不属于任何角色目录**——
**判定：不违反 §2.1**，理由：
1. 它**只有一个写入者**（`framework_admin`），是**单主区**而非多主共享区；
2. 它是**面向人类用户的交付物**，不是角色之间的协作区（角色不写它、也不依赖它完成义务）；
3. 委托层明确指定了该位置。
> 与 `_framework/` 的区别：后者曾被当作"所有角色都要读的规范"使用（多消费者 + 阅读义务），
> 故被移入 `framework_admin/`；本手册**无角色阅读义务**，仅面向人类。
