# _framework/ — framework_admin 的内部档案（**不是共享规范**）

> 所有者: `framework_admin` (R-001) · **唯一写入者**（其余角色只读）
> 定位变更: 2026-09-26（`DECISION-20260926-007`）

## 1. 这是什么

本目录是 **framework_admin 自己的工作档案**，包含四类内容：

| 类别 | 文件 | 性质 |
|---|---|---|
| **立法底稿** | `00-ARCHITECTURE.md`、`05-CONVENTIONS.md` | 我据以**签发**各角色契约的条款源 |
| **登记与图纸** | `01-ROLE-REGISTRY.md`、`04-ROLE-CONTRACT-TEMPLATE.md` | 我的角色登记册与造角色模板 |
| **裁决与审计** | `decisions/`（DECISION 档、AUDIT-LOG） | 我的仲裁结论与违规审计流水 |
| **可复制模板** | `templates/` | 我给自己的骨架底稿 |

## 2. 它不是什么（2026-09-26 明确）

- ❌ **不是"所有角色都要读的共享规范"**。其他角色对它**没有阅读义务**。
- ❌ 不是公共工作空间（`00-ARCHITECTURE §2.1`：本框架不存在公共工作空间）。
- ✅ 其他角色对它**保留只读权限**——用于**溯源**（想知道某条规则从哪来），但**不用于了解自己的义务**。

## 3. 那"通用规则"怎么生效

**通过签发，而不是通过引用。**

> 任何一条对某角色有约束力的规则，都必须**由我裁剪、实例化后写进该角色自己的目录**
> （`role-limit/ROLE-LIMIT.md`、`principles/PRINCIPLES.md`、以及各目录的 `README.md`）。
> 角色**只读自己的目录**，就应当知道该怎么做——这称为 **义务闭合性**（`00-ARCHITECTURE §2.1.1`）。

在本档案里出现的规则文本，是**立法底稿**；对角色生效的是**其契约中的那一份**。
若两者不一致，以**该角色契约**为准（因为它是我最近一次签发的内容），并**由我修正本档案**。

## 4. 阅读顺序（对 framework_admin 自己）

`00 → 01 → 02 → 03 → 04 → 05`。其中 `02-MAILBOX-PROTOCOL.md` 与 `03-MEMORY-MODEL.md`
虽描述通用规则，但它们的**生效方式同样是签发**：各角色的 `mailbox/README.md`、`memory/README.md` 中各有其裁剪版。

## 5. 变更规则

- 本目录**仅 framework_admin 可写**；变更须升版本号并记入 `decisions/`。
- 对角色有影响的变更 → **必须同步更新受影响角色的契约**并 `NOTIFY`（否则即"规范漂移"）。
