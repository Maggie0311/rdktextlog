## 观察 (Observation)
创建 R-002 `management`（用户要求"与 framework_admin 平行同级、统领项目全局"）时，初看有 6 个动作可能同时落在两个角色的"只能做"里：
派活、定验收标准、查交付是否合格、对接人类用户、建角色、判定角色失能。

按"谁级别更高"或"谁管得更宽"去切，6 项全部会陷入拉锯（因为"同级"本身不含任何排序信息）。
改用**层**切分后（元层=谁能做什么 / 执行层=这次谁做什么），6 项在几分钟内全部得到唯一主责裁定，
且每项都能给出可判定的边界（如"契约层 DoD 归 admin、任务层 AC 归 management"）。

## 提炼 (Generalization)
当新增角色与既有角色职责相邻时，**先找切分轴，再写契约**；切分轴应选"变化频率不同的两个层"，
而不是"权限大小"或"管辖范围"。按层切分产出的边界可判定；按级别切分产出的边界必然重叠。

## 待验证 (To Verify)
需在**下一个与既有角色职责相邻的新角色**（例如未来的"验收者/审计者"或第二个调度者）创建时再验证一次：
若按层切分仍不能消除重叠（例如出现无法归层的动作）-> 本经验不成立，需改用"产物归属"或"阶段归属"作为切分轴。

同时待验证其反面：是否存在"层切分过度"的情况——把本可合并的职责切成两层，反而增加通信成本（P6 最小充分）。

## 应用方式 (How to apply)
创建任何与既有角色职责相邻的角色时：
1. 先枚举"可能同时被两边认领"的动作（不写契约）；
2. 对每个动作问"它回答的是'谁能做'还是'这次谁做'"；
3. 归层后指定唯一主责，写进裁定表；
4. 裁定表完成后才动笔写 ROLE-LIMIT。
